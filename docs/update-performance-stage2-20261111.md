# 업데이트 속도 2차 개선 — 휴장일 범위 조회 및 단계별 계측 (2026-11-11)

기존 전체 업데이트 및 최초 자동 조회는 당일 가격이 없으면 이전 5일을 최대 5회 직렬로 조회했습니다. 이 경로를 첫 실패 후 `getPriceHistory(from=T-5,to=T-1)` 한 번으로 대체했습니다. GAS 서버에는 쓰지 않습니다.

- 각 보유 종목은 범위 내 실제 가격 기준일 `sourceDate`가 가장 최신인 값을 택합니다. 미래일·범위 밖·날짜 미확인 값은 제외하고, 다른 기준일 가격을 당일로 승격하지 않습니다.
- 정확한 과거 지정일은 기존 당일 조회 및 수동가격 우선 규칙을 유지합니다.
- 코드 없는 펀드의 기존 90일 NAV 조회는 독립 병렬로 유지합니다.
- 요청 병합 키에 범위 시작일을 넣어 정확 일자와 기간 조회를 구분합니다.
- 전체 업데이트 소요시간을 데이터 복원/가격 재조회/화면 재계산 세 단계로 계측합니다.
- `check-holiday-window-fallback`은 실제 프로덕션 가격조회 함수를 VM에서 실행해 결측·펀드·날짜·휴장일 계약을 검사합니다.

운영 금융 GAS/거래원장·Snapshot·가격이력 변경은 없으며, 서버 측 변경 버전/증분 조회 설계는 #860 종료 후 별도 안전 검토가 필요합니다. 성능 개선의 실제 초 단위 수치는 PC·모바일 측정 전까지 추정하지 않습니다.

## 2026-11-15 — 초기 자동조회/사용자 수동 업데이트 경쟁 제거 및 프로세스 감사

### 확인된 실제 경로
1. 최초 화면: `bootstrapGsheetSettings → getBootstrap`(구형 API에서만 getSettings 호환) → `autoLoadPrices`; 가격 조회는 코드 종목과 코드 없는 펀드 이력을 독립 병렬로 가져옵니다.
2. 상단 **업데이트**: `loadSettings(forcePortfolioRestore:true)`로 미전송 거래 journal·원격 거래/보유를 정합성 확인한 뒤 `getPrices(persist:1)` 및 최종 화면 렌더. 가격/거래 복원을 무작정 생략하거나 자동 polling 결과로 대체할 수 없습니다.
3. 상단 **현재가**와 60초 polling: `getPrices(persist:0)`을 통해 가격만 반영하며 가격이력·Snapshot을 저장하지 않습니다. 동일 요청 병합은 같은 URL·연결 세대·요청 모드에서만 허용됩니다.
4. 데이터 원천은 보유 수량·환율·실제 종가 기준일에 맞춰 보존합니다. 선택한 과거일·숨김 탭·연결 변경·복원 세대 변경 시 늦은 현재가를 화면에 적용하면 안 됩니다.

### 이번 수정
- 초기 자동가격 조회는 수동 전체 업데이트, 수동 현재가 갱신, 과거일 선택 시 새 GAS 요청을 시작하지 않습니다.
- 이미 시작한 자동조회가 끝나기 전에 명시적 복원·계정 연결·기준일·KST 날짜가 변경되면 응답을 화면/로컬 가격 캐시에 적용하지 않고, 이어지는 과거 이력 재요청도 시작하지 않습니다.
- 다른 창에서 변경한 거래·보유를 놓치지 않도록 **전체 업데이트의 강제 복원 및 persist:1은 유지**합니다. 정상 최초 자동조회는 종전대로 실행하고 로컬 가격을 갱신합니다.
- 실제 운영 GAS·거래원장·NAV·Snapshot·브리핑 스케줄·NH API 변경은 없습니다.
- VM 회귀 검증: 정상 초기조회 1회, 선점되어 조회 시작 0회(3종), 진행 중 선점된 늦은 응답 4종 무시, 역사 조회 추가 시도 차단.

### 이후 성능 개선의 검증 기준
- 이미 구현된 `load.full-update`, `load.full-restore`, `load.full-prices`, `load.full-render`, `network.getBootstrap`, `network.getPrices`를 모바일/PC에서 **정상 성공 건** 중심으로 3회 이상 측정해 중앙값·p95 및 병목 비중을 비교합니다. CI 통과는 기기 실측을 대체하지 않습니다.
- GET 시간 제한 90초는 실제 소요시간이 아닙니다. `getPrices`는 원천·가격이력·정확 기준일·Snapshot 쓰기 등 보호된 금융 흐름이므로 원본과 운영 배포 버전의 동등성 없이 병렬화·캐시 생략·persist 제거는 보류합니다.
- GitHub Pages 배포와 GAS 운영 릴리스는 **별개**입니다. `gas-deploy`의 validate 성공 및 deploy skipped는 운영 GAS 배포 성공 증빙으로 간주하지 않습니다.
- 중복 GET/환율 경쟁 방지의 범위는 브라우저 렌더 및 로컬 캐시입니다. 이미 발행한 서버 요청의 취소, 기존 GAS 원격 API 호출량 개선 및 실기기 초 단위 단축률은 검증되지 않았습니다.
