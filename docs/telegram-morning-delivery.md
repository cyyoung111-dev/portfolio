# 텔레그램 장전 시장 브리핑: 운영 및 복구

## 자동 예약 (KST, 한국 거래일)
- NH 코스피200 야간선물 참고값 수집: 07:31 / 07:39 / 07:47 (UTC 전날 22:31 / 22:39 / 22:47).
- Telegram 브리핑 발송: 07:40 / 07:49 / 07:57 / 08:05 (UTC 전날 22:40 / 22:49 / 22:57 / 23:05).
- GitHub Actions의 schedule은 best-effort이며 지연 및 누락 가능성이 있다. 특히 정각 예약을 피하고 기회를 분산한다. 실행 시각은 08:10 전까지만 허용된다. 08:10 이후에는 전송하지 않는다.

## 중복 수집 및 발송 방지
- NH 수집은 동일 날짜 `nh-night-reference-YYYY-MM-DD` artifact의 존재 여부를 GitHub API에서 읽고, 이미 있으면 NH 요청과 추가 업로드를 건너뛴다. 이 검사가 실패하면 fail-closed로 중단한다. 수집은 07:30~08:00 KST, 한국 거래일, `main`의 최초 예약 실행만 허용한다.
- 발송은 동일 날짜 `telegram-morning-claim-YYYY-MM-DD` artifact가 없을 때만 메시지를 준비한다. claim이 먼저 저장되고 전송 API가 호출된다. 모든 예약 시도는 하나의 concurrency 그룹을 사용하고, 재실행(attempt>1)을 차단한다. claim은 14일 보존한다.
- claim은 실제 발송 성공이 아니라 시도 선점을 뜻한다. 실제 성공은 `SENT` 로그로 확인해야 한다. claim 업로드 이후 통신 실패 또는 결과 불명일 때는 중복 방지를 위해 자동 재전송하지 않는다.

## 가격과 운영 검증
- NH artifact는 해당 거래일 06:00 KST 마감 표기, 계약 코드, 틱 크기, 07:30~08:00 수집 시각, 성공한 main의 예약 실행 여부를 모두 검증한다. 유효한 참고값이 없으면 임의 숫자로 대체하지 않고 '미확보'로 발송한다. NH 참고값은 KRX 공식 정산가가 아니다.
- 지수와 환율은 Yahoo Finance의 확인 가능한 전일 일봉만 사용한다.
- `workflow_dispatch`는 '연결 시험' 문자만 보내며 실제 장전 시장 브리핑을 보내지 않는다. 수동 테스트 성공은 다음 거래일의 예약 발송 성공 증거가 아니다.
- GH 예약 이벤트 자체가 생성되지 않는 경우 실행 로그가 없으므로 코드에서 원인을 알 수 없다. 지속적으로 누락되면 외부 예약 트리거를 별도로 구성해야 정시성을 개선할 수 있다. 변경 후 최초 실제 거래일에 NH 수집 artifact, Telegram claim, `SENT` 로그를 각각 확인한다.
