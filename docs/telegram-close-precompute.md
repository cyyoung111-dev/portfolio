# 17:00 마감 브리핑 사전 수집·캐시 — 운영 계약

- **16:50 KST**: 별도 `Telegram closing data precompute` workflow가 NH 미국지수/국내 지수/다우·SOX·VIX/4개 NH 저장 종가/원·달러·DXY·미 10년물 완료 일봉을 병렬로 읽습니다. API 읽기 전용이며 발송·금융 원본 쓰기·NH 토큰 자체 발급 없음.
- 취득 시각은 반드시 **16:45 이상~17:00 미만**. 국내 종가는 **당일 검증된 정규장 마감값**, 미국 값은 **직전 완료 세션**, 환율·금리는 **직전 완료 Yahoo 일봉 참고값**만 허용합니다. 완성하지 못한 원천은 누락으로 보관합니다. 검증된 공개 시장 데이터만 `telegram-close-prepared-YYYY-MM-DD` Artifact에 **2일** 보관합니다.
- **17:00 KST** 마감 워크플로가 기존 **Claim 확인 후** 사전 Artifact를 읽습니다. Artifact의 생성 워크플로명, 경로, schedule, branch, 첫 실행, 성공 결론, 동일 날짜, 생성시각 및 JSON 수신시각·출처·가격유형을 재검증합니다. 불일치·다운로드 지연·미생성은 평소처럼 **실시간 원천 조회**합니다.
- 한 그룹에서 핵심지수 3개/국내 3개/참고 3개/NH 종목 4개/보조 3개가 모두 유효하면 17:00에 해당 그룹을 **재조회하지 않습니다**. 한 개라도 누락되면 해당 그룹만 재조회하고, 검증된 캐시값은 유지한 채 새 유효값을 보완합니다.
- **17:00 / 17:05 / 17:10 / 17:20**, 마지막 허용 **17:29:59 KST**, 17:30부터 전송 금지. 중복 Claim/SENT / 실발송 1회 원칙은 변경하지 않습니다.
- 스케줄러 best-effort 특성상 16:50 실행이 누락되거나 17시까지 완료되지 않을 수 있습니다. 이때 **캐시 미사용=성공이 아님**을 `cacheSource: LIVE_ONLY` 로 구분합니다. 정상 발송 판정에는 실제 `SENT` Artifact와 메시지의 항목별 QC 확인이 필요합니다.
- 새 캐시가 추가된다고 기존 **마감 핵심 6지수 중 1개 확보 시 발송** 정책이 강화·완화되지 않으며, 과거·미확보 가격을 확정 종가로 승격하지 않습니다.

운영 검증: `16:50 schedule → precompute Artifact 생성·타임스탬프 → 17:00 브리핑 cacheSource → 핵심지수 6/6 및 추가 7개 실수신 확인 → 17:30 종료·중복발송 차단`을 각각 확인해야 정상화로 판단합니다.
