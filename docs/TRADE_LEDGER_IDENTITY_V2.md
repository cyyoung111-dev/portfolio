# 거래원장 영구 ID·명시적 변경 계약 v2 (설계·미구현)

> 관련: #734, #860, PR #1012. 이 문서는 **설계 계약**이며 GAS v9.284/341 운영 배포, 개인 원장, 시트 구조를 변경하지 않는다.
> Codex가 계좌를 바꾼 FX 거래에서 원단가·환율 누락을 재현했다. 동일 계좌/종목과 일반거래 multiset만으로는 의도한 삭제와 필드 유실을 구분할 수 없다.

## 1. 확인된 생산 구조와 실패 원인

- 웹의 `genTradeId()`는 거래별 `id`를 생성하고, 편집에서는 기존 `id`를 유지한다.
- 현재 `syncTradesToGsheet()`는 `id`를 전송하지 않고, 승인 GAS v9.284는 거래이력 **A:K 11열**만 저장한다. 서버 `getTrades`에는 영구 ID가 없어 다른 브라우저 복원 시 새 로컬 ID를 부여한다.
- 미배포 FX 후보는 L=`priceRaw`, M=`fxRateAtBuy`를 추가하지만 계좌·종목·11열 비교만으로 저장 의도를 추정한다. 계좌만 수정하면서 FX 정보를 누락하면 '기존 외화 거래 삭제 + 새 일반 거래 작성'과 구분할 수 없다.
- **그룹 비교 조건문 추가로 막지 않는다.** 보유·원가·스냅샷·배당으로 이어지는 거래원장은 수정/삭제를 **영구 ID**로 추적해야 한다.

## 2. 서버 저장 포맷과 권한 계약

- v2 제안: 기존 **A:K 11열 유지**, L=외화단가, M=매입환율, **N=불변 `tradeId`** (총 14열).
- `tradeId`는 계좌·종목·일자·수량·메모와 무관한 식별자다. 동일 종목/동일 일자에 중복된 거래도 **각각 서로 다른 ID**로 유지한다. 이름·코드·계좌 변경에도 동일 ID.
- 새 거래는 충돌 가능성이 낮은 고유 ID를 부여하고 서버가 중복·빈 값·규격 위반을 거절한다. 기존 A:K 레거시는 서버 잠금+백업을 거친 **단일 승인된 마이그레이션**에서 ID를 채운다. 원래 없던 L/M을 추정하지 않는다.
- `getTrades`/Bootstrap/receipt는 `tradeLedgerProtocolVersion:2`, 서버 기준 `ledgerRevision`(A:N 원본의 암호학적 해시 또는 잠금 하 원장 리비전)을 함께 반환한다. 실제 지원 전 광고 금지.
- ID가 이미 존재하는 원장은 **ID 없는 구 클라이언트 전체 덮어쓰기를 저장 전 거절**한다. 배포 인벤토리에서 구 GAS 쓰기 경로를 차단/격리할 때만 실운영 전환한다.

## 3. 수정·삭제 의도 / Compare-and-swap (CAS)

브라우저는 서버에서 받은 `ledgerRevision`과 원장 스냅샷을 보존한다. 이후 저장에는 **전체 결과 원장 + 변경 의도**를 함께 보낸다.

- `create`: 새로운 `tradeId` 및 새 행. 기존 ID 재사용 금지.
- `update`: **기존 `tradeId`** + 그 ID의 이전 행 해시 + 변경 후 행. 수정하는 필드는 계좌/코드/일자/수량/외화원단가/환율 모두 포함 가능.
- `delete`: **기존 `tradeId`** + 이전 행 해시 + 명시적 삭제 의도. 전체 원장에서 단순 누락된 거래는 **삭제로 해석하지 않고 거부**한다.
- 동일 요청의 `create/update/delete`가 중복되거나 충돌하면 거절한다. 서버에 남아야 하는 기존 ID가 빠지거나, 의도에 없는 행이 수정되면 거절한다.
- `expectedLedgerRevision`이 현 서버와 다르면 **쓰기 전 `TRADE_LEDGER_REVISION_CONFLICT`**. 잠금 안에서 재조회/비교 후 저장한다. 사용자는 새로고침·대사 후 재시도하며 자동으로 원본을 덮지 않는다.
- **기존 FX 행 ID를 수정**할 때 L/M이 누락되면, 계좌·코드·일자 변경 여부와 관계없이 `TRADE_FX_METADATA_LOSS_RISK`를 반환하고 **원본 불변**. FX 원천 삭제/정정은 별도 명시 필드·사용자 확인·재검증이 있는 독립 경로로만 허용한다.
- 실제 FX 거래 **삭제**는 `delete` 의도가 같은 ID를 지정하고, 이전 해시와 리비전이 맞을 때만 허용한다. 일반 거래 추가/메모 변경/매도/분할은 기존 FX의 ID·L/M이 보존되면 정상 허용한다.

## 4. 레거시 원본/브라우저 전환 절차

1. v9.284/341의 활성 운영 소스, 단일 배포·Writer 잠금·트리거·시트 A:K 행/수량/원가와 현재 receipt 상태를 **읽기 전용** 대사한다.
2. 별도 GAS v9.285 통합 후보에 **펀드 무변경 skip + FX L/M + 거래 ID N + v2 CAS/의도 계약**을 한 번만 합성한다. 승인 v9.284 소스 자체는 원본 그대로 둔다.
3. 마이그레이션 **복제 원장**에서 11→14열, 기존 중복 거래 1:1 ID 부여, L/M 결측 보존, 날짜/코드/금액과 39종 평가 영향일, 실패 복원 테스트를 먼저 통과한다.
4. 실제 원장 전환은 승인된 시점 단일 Writer Lease + 백업·복구 경로·사전/사후 행 해시 검증을 갖춘 별도 명시적 수동 작업으로 한정한다. 현재 PR/CI는 이 승인에 해당하지 않는다.
5. 브라우저는 **서버 영구 ID를 복원**하며, 기존 로컬 dirty journal이 있는 경우 임의로 서버 ID에 다시 매칭하거나 버리지 않는다. 미확정 매핑은 사용자 검토/격리로 보존한다.
6. 기존 v9.284 `COMPLETE` 영수증은 기존 11필드 해시와 호환되도록 별도 경로로 조회한다. v2 새 요청은 ID·리비전·의도까지 receipt 해시에 포함하고, HTTP ACK 유실 후 동일 요청 재조회 시 재쓰기 없이 `COMPLETE`로 복구한다.
7. 실배포 후 `getTrades` 14열·receipt COMPLETE·브라우저 **PC/Android 새로고침/재접속** 동일 ID/평가액/배당/손익그래프를 확인할 때만 #734의 영구 저장 조건을 완료한다.

## 5. 필수 테스트 오라클 — 실제 생산 함수로 구현할 것

| 시나리오 | 요구 결과 |
| --- | --- |
| 기존 FX 거래 계좌만 수정, L/M 미전송 | `LOSS_RISK`, 저장 0건 |
| 같은 ID FX 거래의 계좌·코드·메모 변경, L/M 정상 보존 | 성공 + ID/L/M/원화단가 정확 readback |
| FX 거래 명시 삭제 + 동일 종목 일반 거래 존치 | 성공, 일반 거래 ID 유지 |
| FX 거래 미선언 삭제(전체 원장에 누락) | 거부, 원본 불변 |
| 동일 종목 일반 거래 신규 매도·분할·메모수정 | 성공, FX 원본 무변경 |
| 같은 날짜/계좌/종목의 완전 동일한 중복 거래 두 건 | ID별 정확 수정·삭제 |
| 구 브라우저의 ID/버전 없는 전체 sync | 기존 ID 원장 변경 전 거부 |
| 서로 다른 브라우저의 리비전 충돌 | CAS 실패, 원장 불변 |
| v9.284 기존 COMPLETE 영수증 조회 | 동일 해시 판정·쓰기 없음 |
| v2 저장 성공 후 HTTP ACK 유실 | receipt 조회로 COMPLETE, 중복 쓰기 없음 |
| 11열→14열 복제 마이그레이션 중단 및 복구 | 백업/저널 보존·재개 검증, 누락/중복 0 |
| FX×매입환율과 KRW 단가 미일치 | 저장 전 오류, 원장 불변 |
| GAS 펀드 no-op 및 기존 NAV 미공표 | lock/write 0; partial 경고 보존 |
| Snapshot 영향일·배당·원가/평가손익 | 원본 수량/매입원가 대사·PC/Android 동등성 |

## 6. 릴리스 차단 조건

- **현재 PR #1012는 Draft·미병합 유지.** FX 안전성 문제가 구조적으로 해소되지 않은 기존 13열 후보를 운영 배포하지 않는다.
- 실제 구현/테스트, 최신 HEAD 독립 리뷰 P0/P1/P2 0건, 전체 CI, 복제 시트 dry-run, GAS 운영 배포 승인, 재접속 영구 저장 확인 전까지 '완료' 표시 금지.
- 금융 원장·가격/NAV·Snapshot·배당, Telegram, GAS 프로젝트·운영 트리거·Secret은 본 문서 작성 과정에서 **변경하지 않는다**.
