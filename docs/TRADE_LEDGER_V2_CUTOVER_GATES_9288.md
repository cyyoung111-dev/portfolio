## 실제 운영 이관 및 수정 허용까지 남은 필수 절차

1. **선행 19시 운영 종료 검증:** 9.287의 펀드/종가/스냅샷
   `COMPLETE`·백업·진행 중 Writer/lease 상태. 마감 실행 시간에는
   이관하거나 GAS를 바꾸지 않는다.
2. **정확한 금융 원본 식별:** 실제 GAS `SS_ID`와 사용자가 조회하는
   원장 스프레드시트가 동일한지, 운영 시트가 정확히 A:K 11열인지,
   기존 338행과 거래 기준일/종목코드/원가/건수의 원본 무결성을
   재확인한다. Sheets의 26개 물리적 열 그리드 수는 데이터
   스키마가 26열임을 뜻하지 않는다.
3. **이관 전 복원 증거:** 모든 A:K 원본 행의 복구 가능한
   독립 백업 + 행별 SHA/원가 합계/고유 ID 대조. 원본
   11열을 14열로 수정하기 전에 배포된 구 Writer 및
   자동 트리거의 경합을 차단한다.
4. **실제 이관 구현/보호:** 현재 후보에는
   `previewTradeLedgerV2Migration` **읽기 전용 프리뷰만** 있다.
   원본에 쓰는 `apply` 경로는 아직 없다. 실제 writer는
   ScriptLock·정확한 원본 fingerprint/헤더/행수·승인된 날짜,
   복원 가능 백업과 단일 실행 토큰·재실행 idempotence가
   검증된 뒤 별도로 구현해야 한다.
5. **서버·클라이언트 동시 호환:** 새로운 GAS release source SHA를
   전체 리뷰 후 고정하고 수동 승인·dry-run·Deployment 읽기
   검증을 완료한다. 웹에서는 정확히 해당 GAS의
   `tradeLedgerProtocolVersion=2`, 14열 header, revision을
   확인한 연결에서만 새로운 거래 저장을 허용한다.
6. **기존 거래 수정 E2E:** 원장 복제본에서 ① 국내 거래 수량/단가
   수정, ② 기존 해외거래 계좌 이동 및 원화·외화단가·환율
   보존, ③ 동일 종목 중복거래 중 특정 ID 1건만 수정/삭제,
   ④ stale PC/모바일 동시수정 CAS 차단, ⑤ 서버 ACK 유실
   후 동일 operationId 재조회·멱등 저장, ⑥ 분할/단주정산,
   ⑦ 삭제 후 재접속/평가손익·배당 검증을 통과해야 한다.
7. **실제 운영에서 소규모 편집 검증 후 확대:** 저장 영수증,
   새 revision, 338개 영구 ID 안정성, A:K 원금/평가/손익과
   Snapshot 대상 날짜를 비교한다. 문제가 있으면 저장을 중단하고
   사전 백업에 따른 정확한 복구 경로를 사용한다.

## 사용자의 기존 거래 수정에 관한 판단

- **v2 승인·이관·운영 E2E가 모두 끝나면** 영구 ID로 특정 거래를
  수정·삭제하고 CAS로 오래된 PC/모바일 상태의 덮어쓰기를 차단하도록
  설계되어 있다. CAS 거절은 데이터 보호를 위한 정상 동작이며
  화면 새로고침 또는 충돌 재조정이 필요할 수 있다.
- 11열 기존 원장에 별도로 기록되지 않았던 **과거 외화 원단가와
  매입환율은 v2가 자동 복원하지 않는다**. 과거 거래를 수정하면서
  FX를 입력할 경우 실제 체결/환전 원본을 대조해야 한다.
- **현재는 기존 거래 수정 무오류를 보증할 수 없다.**
  후속 실제 이관과 실 E2E가 미완료이며, v9.287 운영은 v1이다.
