# 거래·보유 복구 완료 기록

## 저장 및 재시도 계약

완료 기록은 인증된 POST에서만 조회하며, 거래·보유 저장과 같은 ScriptLock 안에서 시작·결과를 기록합니다. 원문은 완료 기록에 넣지 않고 요청 식별번호, 작업 종류, 원본 시트 식별자, 요청·원장 해시, 상태, 시각 및 재계산 영향 날짜만 저장합니다. 최근 64건을 보관합니다. 기록이 없어졌다는 이유만으로 이미 전송한 요청을 다시 쓰지 않습니다.

| 서버 상태 | 판정 | 클라이언트 동작 |
| --- | --- | --- |
| 첫 전송 전 NOT_FOUND | 아직 보내지 않은 새 식별번호 | 기기 전송 의도를 저장·재조회 검증한 뒤 1회 전송 |
| COMPLETE | 요청 해시·시트·현재 원장 및 후속 상태가 일치 | 같은 작업의 원장 재쓰기 생략 |
| BUSY | 잠금 소유자가 실행 중 | 미전송 자료 유지, 재쓰기 금지 |
| STARTED/UNKNOWN | 중단 또는 결과 기록 미확인 | 미전송 자료 유지, 자동 재쓰기 금지 |
| PARTIAL | 거래 원장 저장 이후 재계산 완료 미확인 | 읽기 전용 재검증; 아래 복구 증거를 모두 요구 |
| CHANGED/CONFLICT | 현재 자료 또는 요청/원본 시트가 다름 | 미전송 자료 유지, 자동 덮어쓰기 금지 |
| 전송 이후 NOT_FOUND | 보관 한도·전달 실패·소실을 구분 못 함 | 완료/실패 추정 및 자동 재쓰기 금지 |

## PARTIAL 재검증

대기 마커가 없다는 사실만으로 완료로 승격하지 않습니다. 요청 해시와 현재 원장이 일치하고 원장 쓰기 미검증·pending 마커가 없어야 합니다. 여기에 해당 요청 시작 후의 worker COMPLETED 또는 DEFERRED_RESOLVED 기록, 현재 원장 fingerprint와 worker가 관리하는 source fingerprint의 일치, 영향 날짜 범위의 deferred 해소를 모두 확인합니다. 영향 범위를 확보하지 못한 경우 모든 deferred가 없어야 합니다. 이 판정 자체는 시트·Properties·트리거를 변경하지 않습니다.

완료를 확인한 과거 작업은 새로운 작업 범위의 정상 저장을 막지 않습니다. 반면 미확인 작업은 새 거래가 생겨도 먼저 확인합니다. 작업 범위는 숫자 epoch가 재시작 후 재사용되는 문제를 피하도록 별도의 영속 식별자를 사용합니다.

## 구버전 및 배포 경계

식별번호가 없었던 미전송 기록은 LEGACY_SAVE_UNCONFIRMED로 보류합니다. 새 웹이 먼저 배포되어 구버전 GAS로 전송하는 경우에도 untracked로 남깁니다. 기존 완료 기록이 미확인인데 서버가 기록 API를 지원하지 않으면 구형 쓰기 경로로 우회하지 않습니다. 이 기능의 배포는 기존 휴대전화 미전송 자료의 복구 완료를 뜻하지 않습니다.

## 검증 근거

- 실제 GAS 완료 기록 함수와 실제 웹 확인 함수: ACK 유실, 중복, 불일치, 재시작, 잠금, 저장소 실패, 다른 시트, 완료된 작업 이후 새 저장.
- 실제 보유 저장/읽기 함수: 퍼센트 문자열과 수량·원금 보존, 중복 행 없음. 실제 거래 파싱/검증 경로도 원문 보존 확인.
- 실제 worker 완료 기록 함수와 fingerprint/pending/deferred 조합: PARTIAL 복구 및 부정 사례.
- 실제 Bootstrap/미전송 복구 경로: 전송 순서, 실패 보존, 구버전 미전송·서버 이전 버전 복귀 보호.
- 대표 변이: 동일 요청 중복 방지를 제거하면 중복 쓰기 검사 실패.
- 배포 후에는 가상 식별번호·빈 배열의 읽기 전용 조회만 수행합니다. 실계좌 쓰기나 실제 시간 초과 복구를 운영에서 재현한 것은 아닙니다.
