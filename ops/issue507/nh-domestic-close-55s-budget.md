# Issue #507 — NH PLUG 국내 종가 수집 55초 예산 오프라인 실행 경계

## 직접 확인된 10월 30일 상태
- 운영 시트 2026-10-30에는 국내 주식/ETF 보유 **37개**(종목 마스터와 전부 매칭)가 있습니다. 마스터 구분은 **주식 16 / ETF 21**, 이들 Snapshot은 모두 `KRX_CARRY@2026-10-29`, 당일 가격이력 0/37.
- `PORTFOLIO_CLOSE` 19:34 KST는 `KOSPI 0/1` coverage 실패, 20:37 watchdog도 실패. 그 이전 NH 응답·지연·토큰 상태는 기록되지 않아 원인 **확정 불가**.
- 운영 GAS 고정 v9.281 및 소스 후보 v9.282 모두 `fetchNhRegularCloses`에서 cache miss마다 `Utilities.sleep(1000)`, 전체 경과 `>55000ms`인 다음 종목은 조용히 생략. 첫 NH HTTP 401/403/429 시 나머지 요청도 멈추는 fail-close 설계.
- 37개가 모두 미캐시이면 sleep 최솟값 37초, 55초 내 37개 *전체 요청 완료*에 남는 통신+처리 예산 18초, 즉 종목당 평균 약 **0.486초**. 마지막 요청을 단지 시작하려면 앞선 36회의 평균 통신+처리시간 약 **0.528초** 미만이 필요. API 응답이 느리면 일부 보유종목은 아예 요청되지 않을 수 있습니다.
- 고정시간제한, 인증 중단, 빈 Output_0, 오래된 날짜는 서로 다른 누락 원인입니다. 어떤 경로가 2026-10-30에 실제 발생했는지는 사후 GAS 원본에 증빙이 없어 **UNKNOWN**.

## 실코드 기반 회귀
`scripts/check-issue507-nh-55s-close-budget-source-only.mjs`는 테스트용 **37개 가상 종목**으로 실제 두 GAS 소스의 **동일 함수 본문**을 Node VM에서 실행합니다. GAS `Utilities`/Cache/NH API/시각을 전부 **가상 객체로 대체**하므로 NH OAuth·API·GAS·Sheets 등 외부 호출이 없습니다.

- 가상 응답 지연 400ms: 37/37 정확한 날짜 종가.
- 가상 응답 지연 700ms: 33/37 요청·수신, 나머지 4개는 55초 예산으로 **API 미호출**.
- 첫 요청 401 또는 429: 첫 요청 1건 시도 후 나머지 중단, 0/37.
- HTTP 200이지만 빈 시계열 또는 다른 날짜 37건: 모두 요청되지만 정확 날짜 값 0.
- 인증정보 미구성: 0건 요청. 캐시 전건 hit: 신규 NH 요청·대기 모두 0.
- 모든 테스트에서 금융 원본 쓰기·새 NH 토큰·실제 HTTP 요청 **0건**. 이 모의 실험은 **과거 실패 원인을 확정하거나 실제 보유 종가를 회복한 증거가 아닙니다**.
