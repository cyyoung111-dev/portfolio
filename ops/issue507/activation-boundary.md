# Issue #507 — F00001 단건 복구 운영 통합 릴리스 경계

기준: main 병합 PR #783 (`6f7b1a9c`), 복구 준비 PR #782, 2026-10-30 Snapshot 39행.
이 문서는 **실배포 승인 또는 금융 원본 쓰기 승인서가 아니다.** 현재 전체 후보는 `ops/issue507`에만 있으며, 생산 `src/gas/apps_script.gs` v9.281은 변경하지 않는다.

## 이번 단계 확인

`node scripts/check-issue507-release-boundary.mjs`는 다음 사항을 CI에서 실증한다.

- 현재 9.281 생산 원문은 승인된 Git blob이지만, 555개 함수를 래핑한 통합 후보는 같은 버전의 다른 blob이므로 기존 엄격 배포기가 거부한다.
- 추가 `SERVER_JS` 파일의 비인가 업로드도 거부한다.
- 후보 GAS는 구문상 파싱 가능해도 운영 gate 미초기화 상태에서는 doPost, 수동 펀드 갱신 및 Snapshot 자동 생성의 원래 본문에 진입할 수 없다.
- `BLOCKED` 보고만 생성하며 어떠한 배포, ScriptProperties, 가격/NAV/Snapshot/거래원장 변경도 수행하지 않는다.
- 테스트용 `BLOCKED`는 실제 writer의 가동 또는 안전한 복구 여부를 판정하지 않는다.

## 별도 릴리스의 선행 필수 항목

1. 신규 GAS 버전과 모든 응답의 `gasVersion`, 웹 `EXPECTED_GAS_VERSION`, API 호환성, 배포 문서 및 승인 소스 해시를 동시에 갱신한 최종 **완전한 1개 SERVER_JS 후보**를 별도 PR에서 코드 검토·회귀 테스트한다. 구버전 승인해시를 임의 재사용하지 않는다.
2. 신규 gate를 배포하면 미초기화 상태에서 주요 HTTP/트리거가 차단된다. **서비스 중단이 수반되는 전환**이므로 유지보수 창과 되돌릴 방법을 사전 확정한다. 비계측 구버전 배포가 하나라도 접근 가능하면 전체 writer 배제 판정을 내리지 않는다.
3. Apps Script 모든 실행자·버전의 구 실행 종료, 오래된 배포 차단, 편집기·외부 Sheets API 쓰기 차단을 독립 증빙한다. `script.processes` 403이나 빈 목록을 종료 성공으로 취급하지 않는다.
4. 신규 배포 승인 후 독립 증빙을 바탕으로 해당 `releaseId`의 fresh rollout 확인서를 기록하고, `DRAINING` 상태에서 7분 이상 신규 진입 차단·활성 기록 0건을 확인한다. 과거 주기 확인서 재사용 금지.
5. 5분 이내의 quiescence 확인서, 최신 원천/39행 전체 진단, 승인 binding과 Snapshot 전체 native 백업 readback이 확보되어야만 F00001 기존 한 행 G:K 쓰기를 별도 승인받아 수행한다. F00002 NAV 입력대기 경고·타 38행·다른 날짜·가격이력·원장 보호.
6. 적용 실패나 종료 receipt 누락 시 자동 rollback·재시도·운영 재개를 금지한다. 백업과 현재 원본을 읽기 전용으로 대조하고 별도 복구 승인을 받는다.
