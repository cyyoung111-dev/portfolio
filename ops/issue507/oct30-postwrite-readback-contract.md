# Issue #507 — 2026-10-30 국내 종가 선택 복구의 사후 원본 검산 오라클

## 목적과 경계

- PR #798의 39행 중 국내 37개만 수정하는 **비공개 dry-run 계획**을 승인된 writer의 실제 읽기 후 데이터와 대조할 수 있도록, **별도 순수 JavaScript 검증기**를 작성합니다.
- 아직 승인된 운영 writer는 없습니다. 검증기는 writer가 아니며 어떠한 GAS, Google Sheets API, NH PLUG, Telegram, 금융 원본 또는 외부 서버도 호출하지 않습니다.
- 실제 운영 증빙: 2026-10-30 Snapshot은 39행(국내 KRX_CARRY@2026-10-29 37행, 정상 펀드 NAV 2행), 정확일 국내 가격이력 0/37, 10월 30일 NAV 가격이력 2건, KRX 원천 정확일 37/37. 개별 공식 KRX 종가 37개 값 자체는 아직 확보/저장되지 않았습니다.

## Source-only API 계약

`verifyIssue507Oct30PostState({date,beforeSnapshot,afterSnapshot,beforeHistory,afterHistory,plan})`

- 입력은 **KST 거래일 기준 2026-10-30으로 이미 정규화된 12열 Snapshot / 6열 가격이력**의 보안 프로세스 내부 물리 행입니다. 로컬 검산기가 다른 timezone의 Date 문자열을 임의 변환하지 않습니다.
- 사전 Snapshot 39행 중 국내 37행은 원래 KRX_CARRY, 펀드 F00001/F00002는 FUND_NAV. 사전 가격이력은 NAV 2행. 사후 Snapshot도 **39행·39개 고유종목**, 사후 가격이력은 **39행(기존 NAV 2 + 새 국내 37)**이어야 합니다.
- 국내 37개에 대해서는 **기존 행 인덱스·코드와 원본 행 식별** 및 승인 후 계획한 변경행 전체를 사후 읽기값과 비교합니다. A:F(날짜·코드·명·수량·매수단가·매수원금)와 L(저장일시)은 절대 변경하지 않아야 하고, G:K(평가단가·평가금액·손익·수익률·출처)는 실제 생산 GAS의 가격 KRW 반올림 및 수량·원가 공식과 일치해야 합니다.
- 가격이력 37개는 정확한 날짜, 고유코드, 가격, KRX/KRX_OTP 출처, 빈 timestamp를 계획과 정확히 비교합니다. 전일 또는 YAHOO/NH 임의 승격·중복·부분 삽입을 거부합니다.
- 펀드 2행은 **12열 전체 원형**, 기존 NAV 가격이력 2행은 **6열 전체 원형** 보존을 요구합니다. 날짜 변경·가격 수정·수량/원가 이동·같은 코드 중복·일부 종목 누락과 물리 행 index drift는 모두 실패 폐쇄 처리합니다.
- 출력 가능 객체는 건수만, `safeToFinalize=false` 고정. 이후 별도의 독립된 **동일 잠금 범위**의 증빙/backup signature/readback·다른 날짜 영향 없음·rollback·555 writer gate·원장 동시수정 배제까지 성공해야 실제 복구 완료 처리 가능합니다.

## 검사 및 합성 시나리오

- 동결된 실제 GAS 원본 Git blob `9c1a5f31d1abc4b44f7da9af7a50fe3f15967134` 및 관련 `_verifyCompletedKrxPendingDate_`, `batchUpsertPriceHistory`, `writeSnapshotRows`, `_writeSnapshotDateScoped_`, `_backupSheetBeforeWrite` 함수가 계속 존재하는지 대조합니다. 단 **운영 금융 쓰기 함수는 실행하지 않습니다**.

- 합성 테스트 입력에는 실제 가격, 계좌번호, 종목명, 운영 서명이 없고, 출력 로그에는 개별 코드나 종가를 기록하지 않습니다.
